# 命令出错时的处理

## 找不到 `zentao` 命令或命令不对

找不到 `zentao` 命令时，提示用户执行 `npm install -g zentao16-cli`（需要 Node.js 22.12+）。禅道官方的 `zentao-cli` 包也提供 `zentao` 命令，如果 `zentao --help` 里没有 `bug`、`my`、`resolve` 这些子命令，说明装的是那个包，请用户卸载后改装 `zentao16-cli`。

## 退出码 3：认证、权限或配置问题

先看错误信息：

- **配置或登录问题**：请用户自己设置 `ZENTAO_URL`、`ZENTAO_ACCOUNT`、`ZENTAO_PASSWORD` 环境变量（或写在 `~/.zentao/config.json`），改好后用 `zentao login` 验证。不要让用户把密码贴到对话里。`ZENTAO_URL` 填错时错误信息里会给出应填的地址，原样转告用户。禅道登录加了验证码、单点登录等额外验证时命令行登录不了，需要管理员开一个不走这些验证的账号。证书、代理问题请用户参考 zentao16-cli README 的"兼容性与部署"。
- **权限问题**：提示"没有 xxx 的访问权限"，说明账号缺这项权限；提示"您无权访问该迭代/项目"之类，说明账号缺少单据所属迭代、项目的权限。两种都请用户找禅道管理员开通。

## 写操作失败或结果不确定

- **被禅道拒绝**（比如团队自定义了必填字段；`resolve` 报"状态仍为……（可能缺少必填字段）"也属于这种，说明没有解决成功）：把禅道的提示原样告诉用户，补齐内容后重新给用户看草稿再提交。不要自己编内容去填必填项。
- **`comment` 报没有 action-comment 权限**：如果备注本来就要随转交一起写（比如转给后端排查），可以改用 `zentao assign` 在指派时写备注，但转给谁要由用户确认。
- **其他报"……请到禅道页面确认"的**（备注没出现在历史记录里、指派人没变）：命令提交后会回读单据确认结果，出现这个提示说明写操作可能已经生效。不要直接重试（会重复备注或重复指派），请用户到禅道页面核对。
- **提示"当前为只读模式"**：用户有意开了只读（`ZENTAO_READONLY=1` 或 `~/.zentao/readonly`）。把草稿交给用户，由用户决定是否关闭只读，不要自己去改。
